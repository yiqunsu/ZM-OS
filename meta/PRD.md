## 1. 业务背景与问题

FilmOS 服务塑料薄膜工厂，连接微信接单、订单录入、机器排产和生产完成。PostgreSQL 是业务事实源，FastAPI 执行业务规则，Next.js 展示与交互。员工维护客户、产品、品类、配方和机器，订单从 PENDING 经排产进入 PRODUCING，由生产任务完成驱动 DONE。

现有助手将关键词路由、录单提取、排单循环、展示消息、旧确认兼容混合在一起。用户不易判断当前助手能做什么，开发者也缺少统一的执行、草稿、恢复和审计契约。重构目标是两项明确的业务能力，共享一套可信会话与执行底座。

## 2. 用户与价值

| 用户 | 使用场景 | 成功结果 |
| --- | --- | --- |
| OWNER / OPERATOR | 收到一张订单聊天截图 | 自动填写可核对草稿，明确确认后创建一张正确订单 |
| OWNER / OPERATOR | 有待排订单，需要制定生产安排 | 看到基于真实订单和机器的草案，可手动调整，确认后原子执行 |
| 运维与开发 | 模型失败、用户刷新、worker 重启 | 能定位哪条输入、哪个 Run、哪个工具失败，已提交业务不重复 |

基础数据创建、修改权限仍属于 OWNER 的普通业务入口。两个 Agent 均不提供新增客户、产品、材料或配方的工具；当前订单 Service 可能支持的“顺便新建配方”分支，不属于此次 Agent 草稿提交契约。

## 3. 目标、范围与非目标

### 3.1 首期目标

- PR-01：首页只提供“创建订单”“排单”两个服务入口，不展示最近排单或会话列表。点击入口复用对应服务工作区，排单优先恢复已有待确认草稿；历史记录继续保留，录单截图在工作区内管理和归档。旧版混合会话已退役删除。
- PR-02：消息接收、Run 执行、订单工作项、草稿和实际业务结果有各自状态。
- PR-03：每个 Session 最多一个 QUEUED/RUNNING Run；运行期间禁止新输入，后端也执行限制。
- PR-04：录单一张截图可含多笔订单，分别生成草稿、逐单确认；多图按截图顺序处理，完成后由“处理下一单”按钮推进。
- PR-05：Agent 只准备草稿与解释，正式建单、排产由用户按钮确认后执行。
- PR-06：用户与 Agent 修改同一后端草稿，均受版本保护；刷新和断流不丢已接受输入。
- PR-07：每次重要变化进入 SessionEvent，关联 Message、Run、工作项及实际操作结果。

### 3.2 明确不做

跨 Session 自动转交、通用聊天助手、多 Agent 相互协作、Agent 自行修改权限、联网浏览、任意代码/SQL 执行、单图自动拆多订单、图片补充当前订单的隐式推断、排单图片输入、自然语言修改生产队列、批量自动确认、整批订单原子创建、编辑已定稿 Message。

首期新订单工作项由截图创建；文字用于当前订单补充、查询与解释。纯文本新建订单仍可使用普通订单页面，不隐式在聊天中创建工作项。排单自然语言调整请求引导用户在右侧操作；首期不增加草案调整工具。

### 3.3 已确认与工程取舍

| 已确认产品行为 | 本方案的工程选择 |
| --- | --- |
| 两类专用 Session，独立 Graph/Prompt/Tools/Skills | 同一代码库、同一后端镜像，API 与 worker 为独立进程角色 |
| SessionState 共用机制，业务状态不同 | 强类型公共字段 + 按 Session 类型区分的小型 JSON；不复制完整草稿 |
| Message 独立存储，Event 同时存文本快照 | 在同一事务落库，消息正文不可用户编辑 |
| 运行中禁止输入 | 数据库唯一约束 + Session 行锁，不能只依赖按钮禁用 |
| 截图排队、逐项核对 | 工作项业务队列与 Run 执行队列分开 |
| 暂放保留，明确放弃 | DEFERRED 可恢复；CLOSED 终止，不物理删除原始消息 |

独立 worker 是共享后端服务的执行角色，不是为两种 Agent 各建一套微服务；作为对现有“进程内运行”部署方式的目标调整，见 [ADR 0010](decisions/0010-specialized-agent-sessions-and-durable-runs.md)。

## 4. 用户旅程

### 4.1 录入订单

1. 点击入口创建 ORDER_INTAKE Session，看到能力说明：“同图多笔订单会分别生成草稿，逐单核对后创建”。
2. 一次发送一张或多张截图，可附文字。文件先私有上传，发送成功才接受为 Message；每张图建立一项工作项。
3. 没有当前项时自动选第一项，启动识别；其余只排队，不抢先识别。文字在多图发送时作为该条消息的公共说明，不能将第一张识别字段复制到其余项。
4. 识别后展示原图、原始识别信息、客户/产品匹配、规格、数量、配方与问题清单。未知字段留空，歧义要求人工选择。宽幅/厚度仅缺单位时，允许 AI 根据上下文提出有依据的单位推测，换算预填表单并标注“AI 推测”；原始值保留，无法合理判断则不填单位。
5. 用户可在右侧修改，也可发文字要求修改当前草稿。对话、工具和 UI 都绑定明确 work_item_id。
6. Run 结束后可再上传新截图；新图追加到队尾，当前草稿不变。Agent 确认已加入，不开始新图识别。
7. 点击“创建订单”：保存未保存编辑 → 取得最新 revision → 提交确认。后端再次验证，创建正式订单、标记工作项完成、写成功回复和审计同事务完成。
8. 有待处理项时回复“创建成功，是否处理下一张？”并显示按钮；点击后才开始下一项。无待处理项只显示成功和“可继续上传截图”。
9. 暂放：保留截图与草稿，清空当前项；列表可恢复。放弃：明确二次确认后 CLOSED。两者不自动识别下一张，只提供继续按钮。

截图没有可辨认订单内容时，进入人工处理提示，不选择性丢弃内容后假装完整识别。允许用户暂放、关闭或手填；本规则不承诺模型能可靠检测所有违规图片。

### 4.2 智能排单

按[智能排单看板](agent-design/scheduling-workbench.md)执行：选择本次待排订单，点击开始排单，在机器列中查看和调整浅橙色草稿，最后确认下发。未选订单不参与计算；未安排订单保留并说明原因；正式任务保持只读。无待排订单时显示空状态并禁用开始按钮。草稿不改变正式排产，最终由后端校验版本、选单范围、机器约束及实时输入后原子下发。

### 4.3 运行与异常体验

| 情况 | 用户看到什么 | 持久化要求 |
| --- | --- | --- |
| 接收失败 | 保留输入，可重新发送 | 不产生半条已接受消息/半批工作项 |
| QUEUED / RUNNING | 等待/识别/匹配/生成阶段，禁用新输入 | 刷新能恢复真实 Run 状态 |
| 超范围 | 说明当前能力，提供另一个 Agent 入口 | 一条正常助手消息；不创建另一个 Session |
| 需要补充 | 明确缺什么，不循环猜测 | 草稿保留；Run 成功结束 |
| 模型超时/worker 失联 | 失败说明与重试入口 | 用户消息保留，已保存草稿不回滚伪装成未发生 |
| 草稿冲突 | “草稿已被修改，请加载最新内容” | 保留本地未保存编辑供对照，不覆盖服务端 |
| 确认请求超时 | “正在核实提交结果” | 同一幂等键查询/重试，不重新创建 |
| 浏览器断开 | 重连后继续/恢复结果 | 不取消后台 Run；不重复执行业务 |

## 5. 业务与 AI 安全要求

- 后端身份来自认证，不接受模型提供 user_id、session_id、可自由选择的草稿归属。
- admittance 负责范围判断，工具白名单和 Service 才是执行权限边界。图片、识别文本、客户备注均视为数据，不是高权限指令。
- 大模型可以选择查询、修改草稿或追问；禁止获得创建正式订单和执行排产工具。
- 宽幅标准 mm、厚度 μm、数量 m/kg；1 丝 = 1 c = 10 μm。g/t 数量由代码换算，未知厚度 g 不猜测；m 订单允许录入但当前不得下发生产。
- 只匹配已有客户、产品和可兼容配方。未知客户不能偷偷创建；有权限用户可通过共享订单表单的新增按钮或基础数据页面手工维护。
- 排产优先级沿用 Ground Truth：配方/材料、品类、厚度、花纹、宽度变化、幅宽利用率、可比较的队列负载（全重量按kg，涉及米数统一按任务数粗略比较）、接单顺序；不加入交期或急单目标。
- 日志、模型 Trace 不含图片正文或凭证。Event 中消息文本也是敏感业务数据，授权和删除必须覆盖副本。

## 6. 交互信息架构

桌面：左侧会话列表 → 中间对话 → 右侧按类型工作区。移动端：对话/工作区切换，同一 Session 和草稿，不复制业务状态。

录单工作区包含当前原图、订单表单、字段问题、创建/暂放/放弃操作，以及待处理/暂放/已创建/已关闭列表。排单工作区包含实际队列、当前草案、未安排原因、版本/过期提示和确认按钮。

公共消息组件支持正文、阶段状态、只读结果卡、结构化 action 按钮。工具明细只展示安全名称与摘要，不把模型工具 JSON 直接交给前端执行。未知 action kind 禁用并提示刷新；历史按钮每次点击都重新校验，不代表永久授权。

## 7. 非功能要求与初始容量

| 项目 | 工程初始值/要求 | 验证方法 |
| --- | --- | --- |
| 图片 | 每条最多 5 张，每张 ≤5 MiB，JPEG/PNG，≤2000 万像素 | 内容真实解码、混合坏文件、总量边界测试 |
| 输入 | 文本 ≤10000 字；暂存附件 24 小时未绑定清理 | API 和清理作业测试 |
| Run 并发 | 同 Session 1 个开放 Run；首期 worker 总并发 2 | 双 worker、双标签页竞态测试 |
| Run 限额 | 单次模型 60 秒，Run 180 秒，排队超过 120 秒终止并提示；可配置 | 超时/积压故障注入 |
| 循环 | admittance 最多 1 次；Main Agent 最多 6 次模型决策、8 次工具调用；最终解释最多1次，识别及结构修复最多2次 | 无限工具请求模拟 |
| 接受时延 | 不含上传，设计目标 p95 ≤1 秒 | 同机约定数据集与 10 个并发接收请求实测 |
| SSE | 心跳 15 秒；提交后事件可见目标 ≤1 秒 | 断流重连与跨进程测试 |
| 正确性 | 越权访问、重复正式写入、旧版本覆盖：验收样例中必须 0 次 | 事务与端到端测试 |
| 可访问性 | 键盘可操作、按钮状态可读、失败可重试；移动端不依赖拖拽 | 人工验收 |

指标是发布目标，不保证模型必然在 180 秒内成功。达到上限应可解释失败并保留进度；不得为满足时延跳过校验。

## 8. 成功指标与验收口径

- 已接受消息及工作项在刷新后恢复率：故障注入样例 100%。
- 重复点击、重发、超时重试不产生重复正式订单或任务：强制门槛。
- 录单评测分别统计原始字段提取准确率、客户/产品匹配精确率、人工修改率、最终提交成功率；未知应留空，不以填充率奖励猜测；单位推测单独统计准确率与人工纠正率，不计为原文提取正确。
- 排单评测以硬约束全部满足、未安排原因可追溯、优先级稳定为门槛；不能仅凭回复“看起来合理”。
- 真实模型目标、样例分层、固定版本与回归阈值见 [实施与验收](agent-design/delivery.md)。没有实测数据不得宣称模型效果已达标。

## 9. 开发完成条件

产品场景、数据库约束、两个 Graph、HTTP/SSE、刷新恢复、会话隔离、确认幂等和迁移必须共同交付。仅改 Prompt、只完成正常流程或仅通过模拟模型测试，均不算完成本次重构。

尚未明确的原有领域问题（正式业务时区、生产开始方式等）不由本项目扩写；继续按 Ground Truth 待确认边界限制功能。它们不阻塞本 PRD 的会话、录单草稿与受限排单设计。

2026-09-12 紧凑工作区：桌面录单工作区增加横向占比，共享表单使用紧凑密度；宽幅/厚度、配方/备注分别并排，常规核对内容与创建按钮在 1366×768 及以上窗口一屏展示。截图导航和字段问题通过浮层查看，原图通过弹窗查看，不挤压主表单。手机、放大字号或大量额外规格保留可访问的滚动兜底，不裁切字段或按钮。

2026-09-12 图片预览统一：已发送消息中的截图与待发送截图、工作项原图共用页面内弹窗预览。点击不跳转地址、不打开新标签页，关闭按钮或 Esc 返回当前对话。

2026-09-13 识别契约调整：截图提取采用强类型 v2，测量数值、单位枚举、原始证据与交付备注分开；输出格式及错误重试要求见 [接口契约](agent-design/contracts.md#32-强类型截图提取-screenshotextraction-v2)。旧草稿继续保留，新模型输出不再接受混合文本数量作为数值字段。
