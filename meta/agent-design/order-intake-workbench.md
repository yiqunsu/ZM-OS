# 截图创建订单工作台

状态：已实现，进入本地验收（2026-09-13）。本文更新录单使用流程；排单界面另行讨论。

## 用户与目标

面向不习惯聊天式软件、希望少操作的工厂用户。用户无需学习 Session、Run、Agent 或提示词，只需要上传截图、看图核对、确认创建。

## 最小流程

1. 进入“截图创建订单”，添加一张或多张图片，显示可移除的缩略图。
2. 点击“识别订单”，完成发送与识别启动，不要求附加文字。
3. 用简短进度和图片级失败重试代替思考过程与长篇回复。
4. 自动打开首笔待处理订单：列表导航、左侧原图、右侧自动填写的共享创建订单表单。
5. 用户直接修改字段；缺失和推测问题在对应字段旁提示。
6. 点击“确认创建订单”，按最新草稿完成后端校验及正式创建。
7. 显示创建成功及订单号，自动转到下一笔待处理订单。最后显示本次创建数量和“继续添加截图”，无需再次询问是否处理下一笔。

每张图片可包含多笔独立订单，逐笔核对、逐笔确认。稍后处理保留编辑并转到下一笔；放弃放在次要操作中并确认。切换前保存当前编辑，保存失败留在当前订单并提示。

## 列表命名与状态

主标题格式：`客户名字-产品名-创建日期`。

| 已有信息 | 示例 |
| --- | --- |
| 客户、产品齐全 | 瑞豪-透明膜-2026-09-13 |
| 客户缺失 | 客户-透明膜-2026-09-13 |
| 产品缺失 | 瑞豪-产品-2026-09-13 |
| 两者缺失 | 客户-产品-2026-09-13 |

- 名称跟随当前草稿信息更新；用户明确清空后使用通用名称，不能回填已被清除的识别值。
- 创建日期采用这笔草稿的生成日期，核对或确认时不随当天日期跳变。使用项目统一日期显示规则，不在此另定业务时区。
- 按截图分组，同名项可用组内“第1笔、第2笔”次要文字区分。内部用工作项 ID 定位，不用标题充当标识。
- 名字旁主要状态标签为“待处理”和“已下发”。暂放仍属于待处理，必要时补充次要提示；已放弃项退出默认列表。
- 本页“已下发”仅映射工作项 CREATED，即用户已确认创建正式订单；不表示已分配机器或开始生产，正式订单仍进入待排单。不得因展示用词改变后端生产状态。
- 识别中、识别失败属于截图处理进度，在截图分组位置显示进度或重试，不冒充订单业务状态。

## 页面与代码原则

- 桌面默认展示窄订单列表与左右对照区。截图可放大、移动；切换订单自动显示对应原图。表单复用普通创建订单模块，常用操作和主要字段尽量一屏展示，小屏保证可读和可操作。
- 不展示聊天输入框、思考步骤、工具调用或日常解释消息；保存失败、字段问题、识别失败仍提供简短说明及恢复操作。
- 复用现有 Session、WorkItem、草稿、附件、版本与确认用例，不另建同义业务模型。
- 组件围绕页面组装、订单列表、截图查看、共享表单划分；仅为独立状态或实际复用提取 Hook，避免层层转发和通用工作流框架。
- 按明确的“识别截图”动作执行固定流程，按钮操作无需聊天意图判断。前端读取结构化结果，不解析模型解释来决定下一步。
- 标题和展示标签从已有字段投影，默认不新增重复数据列；保留内部状态和原子确认事务。
- 创建成功而下一笔加载失败时，仍显示创建成功，只重试加载，不能再次创建订单。

## 页面结构与记录管理

全局左侧仅保留业务导航；原“我的会话”常驻栏移除。主区域为订单列表 / 原图 / 共用创建订单表单三栏。列表汇总本人所有录单Session的有效截图，按北京时间日期分组、日内上传时间升序，待处理/已下发/已归档分别筛选，名称过长换行。

移除顶部“录入记录”抽屉、创建新录入及删除录入记录操作。进入服务自动复用后台工作区；旧Session仍保存原数据关联，点击它的待处理草稿时切换后台运行上下文，用户不必管理会话。

每张截图提供次要“归档截图”操作，确认后整图及其订单退出默认列表；在“已归档”可以只读对照原图与订单并恢复。没有自动归档或物理删除，已创建正式订单不受影响。归档中的待处理订单保持草稿，当前ACTIVE项变为DEFERRED；PENDING子项保留状态但不被自动队列选择。恢复不自动创建或识别。

列表按截图服务端分页（每页20张），同图订单不拆页。状态统计来自完整集合，待处理和已下发共享当天编号；归档集合单独编号，归档/恢复/全部放弃后刷新排名。切换前保存草稿，保存或目标选择失败留在当前订单。SSE事件及15秒轻量刷新同步列表，保留已经展开的分页范围；旧记录不通过浏览器全量拉取拼接。

1366×768 与1440×900桌面常用字段和创建按钮一屏显示；小屏通过列表/原图/表单切换，切换不卸载表单，不清除本地修改。图片支持原地弹窗、缩放、拖动。

## 执行与恢复

1. `POST /sessions/{sid}/recognize` 使用现有附件、消息、工作项和 Run 原子接收；要求空正文和1～5张图片。
2. 每图读取数据库候选，通过一次视觉调用提取信息并选择客户/产品；Schema 校验、单位换算、基础数据匹配和整图草稿保存复用现有服务；无聊天范围判断、规划循环和解释模型。
3. Worker 在终态事务创建下一张 NOT_STARTED 图片的持久识别命令及 Run；Session 始终至多一个开放 Run。核对中的工作项不被后台识别目标替换。
4. 图片失败后记录 FAILED，继续后续图片；用户点击该图片“重试”。版本冲突不会无限重排同图，租约丢失后拒绝迟到写回。
5. 所有识别结束后展示第一笔可核对订单；失败图不会阻挡成功图片。核对期间可以再添加图片，新的识别批次仍串行运行。
6. 确认/稍后处理/放弃前先保存修改，命令携带最新 revision 与 advance=true。确认事务包含正式订单、工作项、下一项选择、事件、审计和幂等结果。

数量和单位推测只预填，不等于业务确认。字段问题在原字段旁折叠显示；无法识别、图片损坏、版本冲突等错误有明确重试/恢复入口。
