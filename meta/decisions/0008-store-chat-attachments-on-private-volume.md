# ADR 0008：聊天附件使用后端私有持久卷

- 状态：Accepted
- 日期：2026-08-06

## 背景

智能录单允许用户在聊天中发送 JPG/PNG。图片既是模型识别输入，也是用户消息的一部分。仅把 data URL 保存在浏览器内存会导致刷新后丢失，也无法建立稳定的会话归属授权。直接把最高 5MB 的 Base64 写进聊天 JSON 或 PostgreSQL 会放大数据库、历史接口和备份体积。

当前生产形态是 ADR 0006 确定的单机 Docker Compose，暂未部署 COS，也没有多实例共享存储需求。

## 决策

- PostgreSQL 新增 `ChatAttachment` 元数据，关联到 `ChatMessage`，保存不可猜测 ID、服务端 storage key、MIME、字节数和时间；
- 图片二进制由 FastAPI 写入专用私有持久卷，不进入静态目录、日志、审计 prompt 或 Trace；
- 读取必须经过 FastAPI，并沿附件、消息、会话校验当前用户；Next.js 可用已认证 Route Handler 做同源媒体代理，但不成为授权权威；
- 用户消息与附件元数据作为一个数据库提交处理；文件与数据库跨资源失败采用明确补偿清理；
- 删除会话时同时删除附件；附件卷与数据库使用同一备份时间戳成组备份；
- 第一版每条消息最多一张 JPG/PNG，沿用 5MB 上限。

## 理由

- 完整刷新和重新进入会话都能恢复真实图片，历史不依赖浏览器内存；
- 文件存储避免大体积二进制污染业务数据库和 JSON 历史接口；
- FastAPI 继续是认证、会话归属和数据访问的唯一权威；
- 在当前单机部署上，私有卷比提前引入 COS 更简单，且保留了以后迁移对象存储的清晰边界。

## 后果与限制

- 数据库备份与附件归档必须成组保管；只恢复其中一项可能产生缺失文件或孤儿文件；
- 本机卷仍不能抵御整机或云账号丢失，备份需要定期转移到另一设备；
- 文件系统与 PostgreSQL 不支持统一原子事务，必须测试写文件、提交和删除的补偿路径；
- 多实例部署不能继续使用各实例本地卷，届时需要共享对象存储并重新评估访问 URL、生命周期和备份策略。

## 重新评估触发条件

- 部署扩展为多个 FastAPI 实例；
- 附件数量或容量使本机备份窗口、磁盘或恢复时间不可接受；
- 需要跨区域容灾、自动生命周期、病毒扫描或独立附件保留策略；
- PDF、批量文件或大文件成为正式需求。
